# Sprint 4 Planning

## Goal

Sprint 4 focused on preparing Estalv-IA for the final delivery and presentation. The app already worked in Python, so the main objective was to improve the user value, polish the interface and make the project easier to present and review.

## Starting Point

At the end of Sprint 3, the project had:

- Python dashboard.
- Local JSON storage.
- Transaction and budget flows.
- Unit tests.
- Basic saving recommendations.
- GitHub Actions CI.

## Sprint 4 Work

| Area | Work |
|---|---|
| Product polish | Improved dashboard layout, budgets page and transaction history. |
| Notifications | Added budget alerts and a cleaner notification carousel. |
| Monthly review | Added previous-month summaries and editable saving goals. |
| AI features | Improved AI Advisor and added a hybrid AI Coach with local fallback. |
| Demo readiness | Added demo data, logo, cleaner navigation and final presentation wording. |
| Quality | Expanded tests and reviewed documentation. |

## Definition Of Done

- Main flows work from the browser.
- Demo data shows the product clearly.
- Tests pass locally and in GitHub Actions.
- Documentation explains the product without overloading the repository.
- The final version is pushed to `main`.

## Notes

Some production features are intentionally out of scope for this course delivery, such as user accounts, encrypted storage and a real database. They are listed as future improvements in the technical documentation.
