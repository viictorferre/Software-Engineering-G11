# Sprint 4 Usability Review

## Objective

The goal of this review was to check whether the main Estalv-IA flows were understandable before the final presentation.

Reviewed flows:

- Dashboard overview.
- Add a transaction.
- Filter transaction history.
- Create or update a budget.
- Read AI Advisor suggestions.
- Use the AI Coach conversation.

## Review Tasks

| ID | Task | Expected result |
|---|---|---|
| T1 | Open the dashboard and explain the main indicators | User understands income, expenses, balance and daily limit. |
| T2 | Add a new expense | User can complete the form and save the transaction. |
| T3 | Filter transactions by category | User can find and use the category filter. |
| T4 | Create or update a budget | User understands that limits are monthly. |
| T5 | Read the AI Advisor | User understands the saving recommendation. |
| T6 | Ask the AI Coach a question | User receives an answer based on current data. |

## Observations

| Area | Observation | Action taken |
|---|---|---|
| Dashboard | Some information felt too compressed when demo data was loaded. | Reorganized panels and added scroll areas for long lists. |
| Budget alerts | Multiple alerts occupied too much vertical space. | Replaced stacked alerts with a notification carousel. |
| Transactions | Long history could make the page hard to scan. | Added max-height and internal scrolling. |
| Budgets | Amounts and labels were hard to read in the first layout. | Redesigned budget cards and progress indicators. |
| AI Advisor | Needed clearer structure. | Changed it into a priority insight, goal status, budget risk and next steps. |
| AI Coach | Chat history could grow too much. | Added fixed-height panels and scrollable conversation history. |

## Final Notes

The review helped polish the final demo without changing the product scope. The app is still a course project, but the final version is clearer to present: the dashboard shows the financial situation, budgets are easier to read and the AI sections explain their value more directly.
